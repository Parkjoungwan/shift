**11-16 밤: 공정 1도 깊게 (사용자 요청)**

공정 1 방은 "배우는 방"이라 캐치가 없었는데, 사용자가 공정 1도 깊게 해 달라고 했습니다. 1-2는 사용자가 직접 해 보다가 **예전 배선 1이 조명 없이 풀린다**는 것을 찾아서 다시 설계했습니다. 자세히는 `docs/level-design.md` 실험실 1·2·3 절과 §5-1.

- **실험실 1 「입사」:** 결재 순서가 **모든 단계에** 있고 방이 열릴 때마다 새로 뽑습니다. ①②③ 그대로와 이번 회차 「퇴근」 출구 순서는 빼고 뽑습니다(`avoidOrder`, 출구 순서는 감독관 연습 테이프에만 있어야 함). 1단계는 입구 옆 판에 붙는데 **그 앞 바닥에 선 몸에게만** 읽히고 CCTV·테이프·공개 도면에는 빈 종이입니다. 2·3단계는 판에 "관제실 문의"뿐이고 관제 도면에만 있습니다. 관제 도면(ctrl)은 모든 단계에서 순서와 다음 차례를 봅니다. 순서가 아닌 도장은 반려되고 램프가 다음 도장까지 모두에게 붉게 남습니다. 감독관은 다음 도장을 말하지 않고 순서가 어디 있는지만 말합니다.
- **실험실 2 「상자」:** 상자가 겉모양은 같지만 일부는 비었습니다. 상자 3/4/4개 중 찬 것 1/2/3개(기준 수만큼), 크레인 상자는 늘 참. 빈 상자는 무게 0이고, 압력판에 놓이면 **그 근무가 끝날 때까지 압력판 봉인**(게이트 닫힘, 판 위 상자 못 듦, 공개). 근무가 끝나면 풀리고 빈 상자는 판에 남습니다. 무게는 보행 보조가 들 때 든 사람 화면에만("묵직합니다/가볍습니다", 든 채로 안내 글), 관제 도면은 상자별 적재/빈 글자와 ●/○ 줄(ctrl). 크레인 배선은 그대로 곧음(2-2가 깸).
- **실험실 3 「기호」:** 벽에 이번 발급과 지난 발급 **두 줄**이 똑같이 그려지고, 줄마다 점 꼬리표(1~6)가 붙습니다. 이번 꼬리표는 단말기 화면(그 앞의 카드만, CCTV엔 없음)과 관제 도면(검사하는 줄, ctrl)에만 있습니다. 지난 줄을 넣으면 그 근무 단말기가 바로 잠기고, 그냥 틀림은 한 근무에 2번이면 잠깁니다. 3번 틀리거나 검증을 통과하면 오래된 줄 위에 새로 발급합니다. 서버는 이번 꼬리표(`issue`)와 줄(`row`)만 월드에 싣고, 기호는 벽 앞의 조명에게만 `lab.secret`으로 보냅니다.
- **1-2 「교대 순서」 다시 설계:** 예전 배선 1은 조명 없이 풀렸습니다. 이제 홀 문 하나가 카드 리더(카드)와 감광기(조명)가 **정해진 순서로** 둘 다 승인되어야 열립니다(순서 0 카드 먼저, 1 조명 먼저, 열릴 때마다). 순서가 아닌 쪽은 반려되어 모두에게 붉게 보이고, 다른 쪽이 승인될 때까지 받지 않습니다. 세 장비가 늘 다 필요하고, 두 장비로는 어느 순서도 못 풉니다. 숙련자는 카드를 먼저 보내거나 실험실 1의 순서를 그대로 가져오는데, 이 방의 순서는 따로 뽑습니다. 순서는 관제 도면에만 있습니다.

- **점검:** `test/lab1·lab2·lab3·lab11.test.mjs`가 새 규칙을 다룹니다. 문서 갱신 때 돌려 보니 lab2·lab3·lab11·lab12·labs는 통과, lab1의 `offline: the solo rules draw an order too`가 가끔 실패하던 것은 테스트가 비교마다 순서를 다시 뽑던 탓이라 한 번만 뽑게 고쳤습니다. `node test/i18n.test.mjs` 통과(683키). smoke 162개·campaign 90개도 별도 서버(8790)에서 통과, 한 회차 35근무(단계 2).

## 5. 다시 시작하는 법

```bash
cd gameoff-shift          # 프로젝트 폴더
npm run dev            # http://localhost:8787 (앱의 미리보기 서버 shift-server-2 는 8788)
npm run test:lab       # 방 13개 점검 (서버 필요 없음)

npx tsc --noEmit
```

- **혼자 모드로 특정 방 해 보기:** `http://localhost:8788/?server=127.0.0.1:9&lab=12`
- **관리 페이지:** `/admin/`. 실험실 목록에 공정 2 방도 있습니다. 로컬 토큰은 `.dev.vars`, 운영 토큰은 `.prod-admin-token`. 둘 다 **출력 금지, 공유 금지.**
- **운영 점검:** Windows의 curl은 https에서 `-o`를 쓰면 exit 43이 납니다. node `fetch`나 `https.request`로 합니다.

## 6. 함정 (오늘 겪은 것)

- **브라우저 근무 한도:** 브라우저로 오래 점검하면 그 브라우저 id가 하루 20근무 한도(`daily-limit`)에 걸립니다. `?as=b`처럼 다른 신원을 씁니다.
- **소켓 수 한도:** smoke나 campaign을 돌릴 때 게임 탭을 열어 두면 주소당 소켓 6개 한도(429)에 걸립니다. 관리 페이지로 옮겨 둡니다.
- **연달아 돌릴 때:** 테스트를 연달아 돌리면 분당 연결 10회 한도에 걸립니다. 60초 쉬고 돌립니다.
- **테스트 중 파일 수정:** wrangler dev가 다시 시작돼 smoke가 처음부터 실패할 수 있습니다. 다시 돌리면 됩니다.
- **smoke의 공정 밸브:** smoke는 `stages: 1`로 돌고 끝에 2로 돌려놓습니다. 중간에 멈추면 1로 남으니 관리 API로 되돌립니다.
- **팔레트 후처리:** 3D 장면의 색 변화는 팔레트 후처리에 지워집니다. 눈에 띄어야 하는 효과는 오버레이(2D 캔버스)에 그립니다.
- **새 방을 만들 때 확인할 것:**
  - 선반·다리 사이 간격(1칸 틈은 점프가 어렵습니다)
  - 레버 위 공간
  - 어둠 자르기
  - 오프라인 `local.act`/`enter`/`read`
  - 위 네 가지는 `labs.test.mjs`가 일부 잡습니다.
