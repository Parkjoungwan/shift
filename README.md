# gameoff-shift

GitHub Game Off 2026 (주제 SHIFT) 출품작의 서버 뼈대입니다. 한 건물을 여러 플레이어가 교대 근무로 이어서 진행합니다. 한 번에 한 명만 근무하고, 나머지는 실시간으로 관전합니다.

스토리와 퍼즐 구조는 [docs/concept.md](docs/concept.md)에 있습니다. 지금은 실험실 1~6, 공정 2 방 여섯(1-2~6-2), 마지막 「퇴근」까지 방 13개가 있습니다. 방마다 설계는 [docs/level-design.md](docs/level-design.md), 캠페인 규칙은 [docs/campaign.md](docs/campaign.md)에 있습니다.

## 로컬 실행

```bash
cp .dev.vars.example .dev.vars   # ADMIN_TOKEN 을 원하는 값으로 바꿉니다
npm install
npm run dev                      # http://localhost:8787
npm run smoke                    # 다른 터미널에서, 서버가 떠 있을 때
```

- 게임 화면: `http://localhost:8787/`
- 관리 페이지: `http://localhost:8787/admin/`
- 한 브라우저에서 두 사람을 흉내 내려면 주소 뒤에 `?as=b` 를 붙입니다.
- 특정 실험실부터 해 보려면 관리 페이지의 "실험실" 선택에서 고르고 "이 실험실부터 다시"를 누릅니다. 서버 없이 해 보려면 `?server=127.0.0.1:9&lab=4` 처럼 연결이 안 되는 서버를 주면 오프라인 혼자 모드가 그 실험실에서 시작합니다.

## 화면 구성

- 페이지 전체가 게임 화면 하나입니다. 화면은 640×352 비율을 지키며 창을 채우고, 모든 UI가 그 안에 있습니다. 크기 단위 `--u` 는 화면 폭 640일 때 1px이고, 모든 UI 크기가 이 값의 배수라 창 크기와 상관없이 같은 배치로 커집니다.
- 위쪽 HUD: 화면 이름과 상태, 남은 근무 시간(10초 아래면 빨강), 시계, 연결 상태, 화면 전환 버튼(V), 일지 버튼. 아래쪽 HUD: 닉네임과 출근 버튼, 근무 중에는 쪽지 쓰기와 퇴근.
- 장비 선택, 단말기, 쪽지, 쪽지 보기, 크레딧은 화면 가운데 창으로 뜹니다. 근무일지와 대기열은 오른쪽 서랍(일지 버튼이나 Tab)입니다.
- 감독관 대사는 드론 위 말풍선으로 뜹니다. 드론이 화면 밖이거나 3D가 없으면 화면 위쪽에 뜹니다.

## 언어 (한국어·English·日本語·简体中文)

- 근무자 등록 창 위쪽에서 고릅니다. 고르면 저장하고 페이지를 다시 읽습니다(`public/i18n.js` 의 `setLang`). 처음에는 브라우저 언어를 따르고, `?lang=ko|en|ja|zh` 로 강제할 수 있습니다.
- **한국어 문장이 키**입니다. 화면에 나오는 한국어 문자열은 전부 `t("...")`(값은 `{이름}` 자리)로 감싸고, 데이터에서 온 한국어는 `tr(값)`으로 보여 줍니다. 서버가 비교하는 값(지시문 단어 목록, 오류 코드)은 데이터에서 한국어 그대로 둡니다.
- 사전은 `public/i18n/en.js`·`ja.js`·`zh.js`. 문장을 고치거나 더하면:
  1. `node scripts/i18n-keys.mjs` 로 키 목록(`i18n/keys.json`, 쓰인 곳 포함)을 다시 만들고 빠진 키를 확인합니다.
  2. 세 사전에 번역을 채웁니다. 문체와 용어는 `docs/i18n-style.md`.
  3. `node test/i18n.test.mjs`(`npm run test:lab` 에 포함)가 템플릿 문자열 속 한국어, 빠진 번역, `{자리}` 불일치를 잡습니다.
- 정적 HTML 글자는 `client.js` 의 `translateDom()` 이 바꿉니다. 캔버스 글꼴은 `FONT_FALLBACK`(언어별 시스템 글꼴)을 뒤에 붙입니다. Galmuri에는 가나·한자가 없어 일본어·중국어 글자는 시스템 글꼴로 그려집니다.

## 출입증 사진

- 등록 창에서 출입증 사진을 꾸밉니다(`public/badge.js`, `public/intro.js`). 피부색·머리 모양·머리색·표정·소품·모자·옷·옷 색 8항목. 항목 이름(🎲)을 누르면 그 항목만 무작위, ◀▶로 하나씩, 「전부 무작위」로 전체를 뽑습니다. 배경은 흰색 하나, 색은 바랜 사진처럼 채도를 낮춰 그립니다.
- 사진은 항목마다 36진수 한 자리인 8자 문자열(look)입니다. 서버가 `cleanLook`으로 검사해 이름과 함께 접속 정보·근무일지(`log.look` 열)·녹화·쪽지에 붙입니다. 대기열, 근무일지, 보관소 명단, 크레딧에 얼굴이 나옵니다. 이름이 가려지면 사진도 빈 실루엣이 됩니다.
- 항목은 끝에만 더합니다(문자열 길이가 바뀌면 예전 look이 무효가 되어 실루엣으로 보입니다).

## 관제 화면과 현장 (화이트칼라·블루칼라)

같은 방을 직급에 따라 다르게 봅니다. 기획은 `docs/two-views.md` 에 있습니다.

- **관제 화면 (근무하지 않는 모든 사람):** 남색 2D 도면입니다. 벽은 윤곽선, 장치는 아이콘과 상태 글자("차단기 OFF", "도착까지 32초"), 근무자는 점과 번호, 잔상은 초록 점선 경로로 보입니다. 오른쪽에 장치 상태 목록과 근무자, 아래에 오늘의 지표(진행, 근무 수, 시간 초과율, 인수 거부)와 "미분류 문서 1건 · 판독 불가"가 있습니다. 실제 3D 방은 오른쪽 위 작은 CCTV 창으로 줄어듭니다. V 키나 위쪽 버튼으로 CCTV를 크게 볼 수 있습니다.
- **관제 화면에 없는 것:** 자외선 기호(판독 불가 상자로만 표시), 어둠 속 모습(빗금과 "조도 미달"). 시스템이 아는 것만 보이고, 몸이 있어야 아는 것은 현장에서만 보입니다.
- **배선층 (관제 근무만, 2026-11-16 저녁):** 무엇이 무엇에 연결됐는지(1-2 승인 순서, 2·2-2 크레인 버튼 배선, 3 단말기가 검사하는 줄과 그 꼬리표), 숨은 타이머(4 도착 지연과 카운트다운, 4-2 닫힘 지연), 실제 값(1 결재 순서와 다음 차례(모든 단계), 2 상자마다 찬 것/빈 것, 5·5-2 방 위상, 퇴근 마지막 오입력)은 **관제 근무 중인 사람**의 화면에만 나옵니다. 대기자·관전자·퇴근한 사람에게는 가림 막대(`█▀█▀`)입니다. 배선 선과 글은 빠지고, 장치는 아이콘과 이름만, 상태 줄은 이름만 남습니다. 기준은 "어디에 무엇이 있는지는 공개, 연결·숨은 타이머·실제 값은 비밀"입니다.
- **배선을 정하는 쪽:** 실험실 모듈의 `schematic()` 이 항목이나 상태 줄에 `ctrl: true` 를 붙이고, `console.js` 의 `cleared()` 가 권한(`opts.clearance`)에 따라 가립니다. 현장 그림(벽, 램프, 3D, 안내 글)에도 섞인 배선은 그리지 않습니다. 관제를 아무도 안 골라도 막히지 않습니다. 해 보면 결과가 모든 CCTV와 테이프에 남습니다.
- **기록 보관소는 전부 보입니다:** 깬 방의 재생은 배선까지 그립니다. 지금 방의 배선만 비밀입니다.
- **녹화 대장 (지금 방 되감기):** 대기·관전 중에 위쪽 HUD의 「녹화 대장」을 누르면 지금 열린 방의 지난 근무를 보관소 열람 창에서 이어 봅니다(`room.tapes`, 최신 120개, 사람당 시간당 30번). 배선은 여기서도 가립니다. 아래 **사건 띠**에 근무 시작(장비 색), 산재, 시간 초과, 인수 거부, 단말기 입력 결과(넣은 기호는 안 남김), 기호 교체와 이유, 쪽지, 핀, 도장이 표시되고, 누르면 그 순간으로 갑니다. 열람 중에 차례가 오면 재생이 멈추고 알립니다. 설명은 `docs/two-views.md` 11절.
- **현장 화면 (근무자):** 카메라가 근무자 등 뒤 낮은 각도에서 넓은 화각으로 따라가며, 가는 방향을 앞쪽에 보여 줍니다. 판정은 그대로 2D 평면이고 보는 각도만 바뀝니다.
- **전환:** 출근하면 작은 CCTV 창이 화면 전체로 커지면서 카메라가 근무자 등 뒤로 내려갑니다. 퇴근하면 반대로 줄어들고, 도면이 왼쪽부터 다시 그려집니다.
- 실험실 모듈은 `schematic({ world, now, actor, echo })` 로 도면에 올릴 장치(`map`)와 상태 목록(`status`)을 돌려줍니다. 형식은 `public/console.js` 맨 위에 있습니다.

## 화면 구성 (3D)

- 게임 판정은 모두 2D 평면(실험실 모듈)에서 일어나고, `render3d.js` 가 그 평면을 3D로 그립니다. 벽, 문, 빛 발판, 간판은 렌더러가 지도에서 만들고, 단말기·레버·엘리베이터 같은 장치는 실험실의 `build3d(kit)` 가 만듭니다.
- 어둠, 기호, 쪽지, 전광판 글자, 이름표는 2D 겹침 캔버스(월드 좌표, 2배 해상도)에 그리고, 그 캔버스를 3D 안의 z = 0 평면에 붙입니다. 그래서 정면 카메라든 근무자 등 뒤 카메라든 3D와 정확히 겹칩니다. 쪽지 위에 마우스를 올렸는지는 그 평면에 광선을 쏴서 판정합니다.
- 픽셀 렌더링이 기본입니다. 3D를 320×176으로 그려 뭉개지 않고 키우고, CCTV 카메라는 렌더 픽셀 단위로 맞춰 움직입니다. 조작 안내 글자만 화면 해상도로 선명하게 그립니다. 주소에 `?pixel=0` 을 붙이면 매끈한 화면, `?pixel=3` 이면 더 거친 화면입니다.
- 픽셀 모드에서 1픽셀보다 가는 물체는 끊겨 보이므로, 난간·발광선·레버처럼 가는 물체는 0.13칸 이상 두께로 만듭니다. 간판 글씨는 5×7 비트맵 글꼴입니다.
- WebGL을 쓸 수 없으면 같은 방을 2D로 그립니다.
- 가볍게 유지합니다. 후처리(빛 번짐)는 쓰지 않고, 점광원은 조명 근무자의 손전등 하나뿐입니다. 해상도는 화면에 보이는 크기에 맞추고(최대 1.25배), 그리기는 화면 갱신(requestAnimationFrame)에 맞춥니다. 게임 판정은 별도 타이머로 돌아 숨은 탭에서도 멈추지 않습니다.
- 근무자 로봇은 Three.js 기본 도형입니다. 소품과 감독관 드론은 아래 CC0 모델입니다.

## 소리

소리 파일은 하나도 없습니다. 모두 `public/sound.js` 가 Web Audio API로 그 자리에서 합성하므로, 받을 파일도 라이선스도 없습니다.

- **배경음은 시점을 따라갑니다:**
  - **관제 화면(대기·관전):** 사무실 소리입니다. 전원 험, 형광등 웅웅거림, 공조기 바람에 가끔 키보드 소리가 섞입니다.
  - **현장(근무 중):** 공장 소리입니다. 숨 쉬듯 오르내리는 기계음, 환기 덜컹거림, 먼 곳의 쇳소리가 납니다.
  - **CCTV를 크게 볼 때:** 둘이 옅게 섞입니다.
- **음악:** 관제 화면에서만 단조의 느린 로비 음악(감독관이 생각하는 쾌적한 직장)이 나오고, 출근하면 사라집니다.
- **효과음:** 점프, 착지, 장치 승인·반려, 단말기 키, 도장, 쪽지 붙이기, 감독관 말소리, 산재(감전과 경보), 진행, 방 완료, 출근·퇴근 펀치, 차례 알림, 마지막 10초 초침이 있습니다. 실험실 6에는 발판 흔들림·떨어짐, 6-2에는 00초 종소리가 더 있습니다.
- 브라우저는 사용자 입력 전에는 소리를 낼 수 없어서, 첫 키 입력이나 클릭에서 소리를 켭니다. 위쪽 HUD의 「소리」 버튼으로 끄고 켜며, 이 브라우저에 기억됩니다.
- 실험실 모듈은 `tick(api)` 에서 `api.sound(이름)` 으로 효과음을 낼 수 있습니다.

## 실험실 3 「기호」

근무 세 번으로 끝나는 정보 인계 퍼즐입니다.

1. **조명:** 어두운 수직 통로를 빛 발판으로 올라가 벽의 자외선 기호를 봅니다. 빛 발판은 조명이 비출 때만, 위에서 밟을 때만 단단합니다. 기호는 조명 근무자 화면에만 보이고 관전 CCTV에는 찍히지 않습니다.
2. **출입 카드:** 단말기에 기호 4개를 순서대로 입력해 문을 엽니다. 기호를 본 적이 없으니 쪽지에 기대야 합니다.
3. **보행 보조 장치:** 점프가 높아 4칸 높이 선반을 오를 수 있습니다. 문 너머 선반을 올라 레버를 당기면 공정 2 방 3-2 「갈라진 기호」로 넘어갑니다(공정 밸브가 1이면 실험실 4).

**두 줄 (11-16 밤):** 벽에는 이번 발급의 줄과 지난 발급의 줄이 똑같이 그려져 있고, 줄마다 앞에 점 꼬리표(주사위처럼 점 1~6개)가 붙습니다. 어느 줄이 이번 것인지는 단말기 화면(그 앞에 선 출입 카드에게만)과 관제 근무 도면만 압니다. 그래서 조명은 두 줄을 꼬리표째 베끼고, 카드는 단말기의 꼬리표로 고릅니다.

- 지난 발급의 줄을 넣으면 그 근무의 단말기가 바로 잠깁니다. 그냥 틀린 입력은 한 근무에 2번이면 잠깁니다. 잠김은 근무가 끝나면 풀리고, 모두에게 보입니다.
- 모두 3번 틀리거나 검증을 통과하면(2·3단계) **오래된 줄 위에** 새 기호와 새 꼬리표를 덧칠합니다. 방금까지의 줄은 벽에 남아 미끼가 됩니다.

공개 도면에는 「기호 발급 N차」가 나오고, 녹화 대장의 사건 띠에 「기호 교체」가 이유와 함께 붙습니다. 쪽지가 교체 전에 쓴 것인지 가리는 데 씁니다.

조작은 ←→ 또는 A D 이동, Space 또는 ↑ 점프, E 또는 ↓ 조작, 단말기에서는 숫자 키 1~6입니다.

### 정답 보안

- 벽의 기호(두 줄 모두)는 서버에만 있습니다. 현장 상태와 관전 중계에는 들어가지 않습니다.
- 조명 근무자가 벽 앞에 서면 클라이언트가 `lab.read` 를 보내고, 서버는 그 근무자에게만 `lab.secret` 으로 벽 전체(두 줄과 꼬리표)를 보냅니다.
- 이번 발급의 꼬리표(`issue`)와 검사하는 줄(`row`)은 월드에 실려 갑니다. 단말기 화면과 관제 도면에 필요해서입니다. 기호는 하나도 들어 있지 않습니다.
- 단말기 입력은 `lab.enter` 로 서버가 판정합니다. 출입 카드 근무자만 보낼 수 있습니다.
- `door`, `tries`, `gen`, `seen`, `passes`, `issue`, `row`, `locked`, `stale` 은 서버가 정합니다. 근무자가 현장 상태를 고쳐 보내도 서버 값으로 덮어씁니다. 문이 닫혀 있으면 레버도 내려가지 않고 클리어도 인정되지 않습니다.
- 남은 허점이 있습니다. 위치는 여전히 클라이언트 말을 믿으므로, 조명 근무자는 개발자 도구로 벽까지 가지 않고 정답을 받을 수 있습니다. 자기 근무의 재미만 깨는 부정이라 지금은 두었습니다.
- 오프라인 혼자 모드는 같은 규칙을 브라우저 안에서 흉내 냅니다. 이 모드에서는 정답이 브라우저 메모리에 있습니다.
- **배선은 월드에 실려 갑니다 (알고 둔 허점):** 섞인 배선과 비밀 값(1 `order`(모든 단계), 1-2 `wire`, 2 `weights`, 2-2 `wiring`, 3 `issue`·`row`, 4 `arriveMs`, 4-2 `badge`·`delays`, 5·5-2 `phase`)은 근무자 화면이 시뮬레이션하려면 필요해서 공개 월드에 들어 있습니다. 공개 도면과 현장 그림에는 안 그리지만(관제 도면에는 ctrl로만) 개발자 도구로는 읽힙니다. 2의 `weights`는 든 사람의 손(무게 대사와 안내 글)에도 씁니다. 3의 기호, 3-2의 명판·자외선 기호와 「퇴근」 입력 순서는 서버에만 있고, 그 앞에 선 근무자(3, 3-2)나 보관소 테이프(퇴근)로만 나갑니다.

## 실험실 4 「엘리베이터」와 잔상 기록기

시간 인계 퍼즐이고, 새 장비 잔상 기록기가 처음 나옵니다.

- **잔상 기록기:** 근무 중 마지막 8초의 움직임이 녹화됩니다. 퇴근하면 그 8초가 반투명 초록 로봇(잔상)으로 방에 남아 다음 근무 동안 계속 반복합니다. 잔상은 안전 버튼을 누를 수 있지만 레버·차단기는 못 씁니다. 다음 잔상 기록기 근무자가 퇴근하면 덮어씁니다.
- **안전 버튼 두 개:** 1층 양 끝에 있어 한 사람이 동시에 누를 수 없습니다. 근무자가 한쪽, 잔상이 다른 쪽을 누르고 있고 차단기가 올라가 있으면 엘리베이터가 호출됩니다.
- **차단기:** 출입 카드만 올리고 내릴 수 있습니다.
- **엘리베이터:** 호출하면 위층에서 떠나 30~50초 뒤 1층에 도착하고, 10초 동안 문을 열고 기다린 뒤 위층으로 올라갑니다. 지연은 방이 열릴 때마다 서버가 1초 단위로 정합니다(`lab4core.js` `DELAYS`, 그 전 월드는 45초). 보통 호출한 근무가 아니라 다음 근무에 도착합니다.
- **지연을 아는 곳:** 1층 문 위 전광판 숫자는 현장의 몸에게만 보입니다. CCTV·테이프에는 전광판 램프 색(대기 → 노랑 → 초록)만 찍힙니다. 관제 근무는 도면에서 지연과 카운트다운을 봅니다. 그 밖에는 녹화 대장에서 호출부터 도착까지를 재야 합니다. 호출 알림 대사에는 초가 없습니다.
- **위층:** 4칸 선반 두 단 위에 퇴근 레버가 있어 보행 보조 장치가 필요합니다.

정해법은 잔상 기록기(왼쪽 버튼 위에서 퇴근) → 출입 카드(차단기 올리고 오른쪽 버튼) → 보행 보조 장치(엘리베이터 타고 올라가 레버)입니다.

판정은 이렇게 나뉩니다.

- 잔상은 서버가 기록합니다. 근무자가 퇴근할 때 보낸 자기 8초 기록을 쓰고, 연결이 끊기는 등 기록이 안 오면 서버가 받은 위치로 만듭니다.
- 엘리베이터 호출 시각(`callAt`)과 호출 횟수는 서버가 정합니다. 근무자가 고쳐 보내도 덮어씁니다. 호출이 한 번도 없으면 레버도 클리어도 인정하지 않습니다.
- 엘리베이터 위치와 잔상 위치는 서버 시각과 `callAt`·잔상 기록만으로 계산하므로 모든 화면에 똑같이 보입니다.
- 위치는 여전히 클라이언트 말을 믿습니다(실험실 3과 같은 허점).

## 규칙 요약

- 처음 들어오면 근무자 등록 창이 뜹니다. 기본 이름은 없고, 직접 입력해야 출근할 수 있습니다. 등록하지 않아도 관전은 됩니다. 이름이 비었거나 금지어면 서버가 거부하고 다시 입력하게 합니다(`nick-required`).
- 접속하면 관전자입니다. `출근 대기`를 누르면 대기열에 들어갑니다.
- 차례가 오면 20초 안에 캐릭터를 고릅니다. 이때 `인수 거부`를 켜면 직전 근무를 되돌리고 시작합니다.
- 근무자의 위치는 초당 10번 서버로 가고, 서버는 저장 없이 관전자에게 그대로 넘깁니다.
- 현장 상태는 근무자가 `checkpoint` 와 `shift.end` 로 보낼 때만 저장됩니다.
- 근무는 한 번에 60초로 제한됩니다. 퍼즐은 한 근무자가 그 안에 자기 몫을 풀 수 있게 만듭니다. 쪽지는 퇴근 뒤 60초 동안에도 쓸 수 있어 근무 시간을 잡아먹지 않습니다. 제한 시간은 관리 페이지에서 바꿀 수 있고, 그 값은 서버에 저장되어 기본값보다 우선합니다.
- 90초 동안 입력이 없으면 자동 퇴근입니다.
- 그림 쪽지는 근무 한 번에 1장입니다(N 키 또는 「쪽지 남기기」). 근무 중에는 서 있는 자리에, 퇴근 뒤에는 60초 안에 퇴근한 자리에 남길 수 있습니다. 같은 자리에 여러 장이 겹치면 한 묶음으로 쌓이고, 장 수가 표시되며, 눌러서 한 장씩 넘겨 볼 수 있습니다.
- 쪽지는 신고 1회에 흐려지고 2회에 숨겨집니다. 닉네임은 신고 2회에 `익명 근무자`로 바뀝니다.
- 출구에 도착하면 하루가 끝나고 크레딧이 나온 뒤 새 근무일이 시작됩니다.
- 서버에 4초 안에 연결되지 않으면 클라이언트는 오프라인 혼자 모드로 바뀝니다.

한도 값은 모두 `src/shared.ts` 의 `LIMITS` 에 있습니다.

### 요청을 아끼는 구조와 한도

무료 플랜은 하루 약 10만 요청입니다(새 연결 1건, 들어오는 WebSocket 메시지 20개에 1건, 나가는 메시지는 세지 않음).

- **움직임은 실시간으로 보내지 않습니다.** 근무자는 60초를 0.1초 단위로 기록해 두었다가 퇴근할 때 한 번에 보냅니다(CCTV 녹화 테이프). 관전자와 새로 들어온 사람은 그 테이프를 약 1분 늦게 봅니다. 근무 1번의 요청은 몇 건뿐이고, 관전자 수와 상관없습니다.
- **잔상 기록기**는 퇴근 때 보낸 마지막 8초로 잔상을 만들고, 없으면 테이프 끝부분에서 만듭니다. 연결이 끊긴 근무에는 테이프도 잔상도 남지 않습니다.
- **연결 하나:** 10초에 60개 넘게 보내면 끊습니다(1008).
- **사람 한 명(client id):** 출근 신청 분당 12번, 근무 시간당 45번, 신고 시간당 10번, 반응 시간당 30번, 접속 인사 분당 10번. 넘으면 `rate-limited` 오류.
- **주소 하나(Worker가 날짜를 섞어 해시한 값, 주소 자체는 저장하지 않음):** 동시 연결 6개, 분당 새 연결 10번. 넘으면 429.
- **건물 전체:** 시간당 3,000건(하루 최대 약 7만 2천). 다 쓰면 새 연결은 503, 메시지를 보내는 연결은 1013으로 끊고, 브라우저는 다시 두드리지 않고 혼자 모드로 넘어갑니다. 끊긴 연결은 2, 4, 8 … 60초 간격으로 6번까지만 다시 연결합니다.
- 관리자 API `/state` 의 `budget` 에서 이번 시간 사용량을 볼 수 있습니다.
- 한도는 메모리에 있어서 건물이 잠들면 초기화됩니다. 잠드는 건 조용할 때뿐이라 괜찮습니다. 로컬에서는 모든 접속이 같은 주소라 smoke 테스트를 1분 안에 두 번 돌리면 분당 연결 한도에 걸릴 수 있습니다.
- Cloudflare 대시보드의 무료 속도 제한 규칙 1개로 `/ws` 를 IP당 묶어 두면, 요청이 Worker에 닿기 전에 막아 Worker 한도까지 아낄 수 있습니다.

## itch.io 올리기

1. `npm run deploy` 로 서버를 배포합니다. 운영 관리 토큰은 `.prod-admin-token`(git 제외)에 있고, 배포 때 비밀값으로 함께 올렸습니다.
2. `npm run build:itch -- <서버 호스트>` 로 `dist/gameoff-shift-itch.zip` 을 만듭니다. 관리 페이지는 빠지고, 서버 주소가 index.html 에 들어갑니다.
3. itch.io 프로젝트에 zip을 올리고 "This file will be played in the browser"를 켭니다.

2026-11-15에 초안 프로젝트(`nonoiseplz.itch.io/handover-shift-test`, Draft)로 확인했습니다. itch.io 웹 플레이(출처 `https://html-classic.itch.zone`)에서 WebSocket 연결, 출근 대기, 차례 배정이 모두 됐습니다.

공개 전에 할 일:
